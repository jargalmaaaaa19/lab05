## 1. Тестлэх систем

"Хичээлд бүртгүүлэх" REST API (`server.js`, цэвэр Node.js, `http://localhost:3000`). Тестлэгдэх функц нь `POST /registrations` бөгөөд `PUT /students/:id`, `PUT /courses/:id` хүсэлтүүдийг тест бүрийн setup (Initialization) болгон ашигласан.

## 2. Тест дизайн

### 2.1 Сонголт ба төлөөлөх утгууд

| № | Сонголт | Эквивалент анги | Төлөөлөх утга |
|---|---|---|---|
| 1 | studentID-гийн хүчинтэй байдал | идэвхтэй | `PUT /students/S01` `{"status":"active", ...}` |
| | | идэвхгүй | `PUT /students/S03` `{"status":"inactive", ...}` |
| | | байхгүй | PUT хийгээгүй ID |
| 2 | Оюутны үзсэн хичээлүүд (`coursesTaken`) | урьдач нөхцөл хангана | `["CS201"]` |
| | | урьдач нөхцөл хангахгүй | `[]` |
| 3 | courseID-гийн хүчинтэй байдал | байгаа | `PUT /courses/C01` |
| | | байхгүй | PUT хийгээгүй ID |
| 4 | Хичээлийн урьдач нөхцөл (`prerequisites`) | бүгдийг нь үзсэн | `["CS201"]`, оюутан `["CS201"]` үзсэн |
| | | огт үзээгүй | `["CS201"]`, оюутан `[]` |
| | | зарим нь | `["CS201","CS202"]`, оюутан зөвхөн `["CS201"]` үзсэн |
| | | урьдач нөхцөлгүй (хязгаар) | `[]` |
| 5 | Хүсэлтийн бүтэц | бүрэн | `{"studentID":..., "courseID":...}` |
| | | талбар дутуу (хязгаар) | `{"studentID":"..."}` (courseID-гүй) |

**Боломжгүй хослол:** байхгүй оюутанд `coursesTaken` гэж байхгүй, байхгүй хичээлд `prerequisites` гэж байхгүй. Тиймээс "оюутан байхгүй" эсвэл "хичээл байхгүй" ангитай урьдач нөхцөлийн сонголтыг хослуулах утгагүй.

**Шалгах дараалал (сервер):** талбар дутуу → оюутан байхгүй → оюутан идэвхгүй → хичээл байхгүй → урьдач нөхцөл. Хоёр алдаа зэрэг гарвал жагсаалтад түрүүлж байгаа нь буцна. Давхар алдааны тестүүд үүнийг баталгаажуулна.

### 2.2 Спецификацийн хүснэгт

| № | Төрөл | Postman folder | Нөхцөл | Хүлээгдэх статус | Хүлээгдэх result |
|---|---|---|---|---|---|
| 1 | Happy path | T1 Happy path: амжилттай бүртгэл | идэвхтэй оюутан, CS201 үзсэн, хичээлийн урьдач CS201 | 201 | `OK` (registrationID тоо) |
| 2 | Алдааны анги | Идэвхгүй оюутан бүртгэх | оюутан идэвхгүй, хичээл байгаа | 200 | `ERROR_INACTIVE_STUDENT` |
| 3 | Алдааны анги | Оюутан байхгүй | PUT хийгээгүй studentID, хичээл байгаа | 200 | `ERROR_NO_STUDENT` |
| 4 | Алдааны анги | Хичээл байхгүй | идэвхтэй оюутан, PUT хийгээгүй courseID | 200 | `ERROR_NO_COURSE` |
| 5 | Алдааны анги | Холбоос хичээл үзээгүй | идэвхтэй оюутан, `coursesTaken=[]`, урьдач CS201 | 200 | `ERROR_PREREQUISITES` |
| 6 | Давхар алдаа | оюутан ба хичээл хоёулаа байхгүй | studentID ба courseID хоёулаа байхгүй | 200 | `ERROR_NO_STUDENT` (оюутны шалгалт түрүүлнэ) |
| 7 | Давхар алдаа | идэвхгүй + холбоос дутуу | оюутан идэвхгүй, мөн урьдач нөхцөл дутуу | 200 | `ERROR_INACTIVE_STUDENT` (идэвхгүй байдал урьдачаас түрүүлнэ) |
| 8 | Хязгаар | Холбоосгүй хичээл | урьдач нөхцөлгүй хичээл (`prerequisites=[]`), `coursesTaken=[]` | 201 | `OK` |
| 9 | Хязгаар | courseID дутуу | хүсэлтэд courseID талбар байхгүй | 400 | `ERROR_BAD_REQUEST` |
| 10 | Happy path (Даалгавар 1) | lab05 (collection-ий төгсгөл) | оюутан `B231234567` (идэвхтэй, CS201 үзсэн), хичээл `CS313` (урьдач CS201) | 201 | `OK` |

Тест бүр өөрийн ID-тай, өөрийн setup-тайгаа бие даасан (test independence). registrationID-ийн яг утгыг шалгаагүй, зөвхөн тоо байгаа эсэхийг шалгасан (сервер ажиллах хугацаанд ID нэмэгддэг тул).

## 3. Collection

- `lab05-collection.json` нь 10 тесттэй, тест бүр 2 oracle-той (статус код + `result` утга). Бүх хүсэлт `{{baseUrl}}` (`http://localhost:3000`) collection variable ашигласан.
- `lab05-collection-fail.json` нь үндсэн collection-той яг ижил, зөвхөн T1-ийн нэг oracle-ийг зориуд буруу болгосон (201-ийг 200 гэж хүлээсэн).

## 4. Newman ажиллуулалтын үр дүн

Бүтэн текст гаралт нь `results/` хавтсанд байна.

| Ажиллуулалт | Файл | assertions executed | assertions failed | exit code |
|---|---|---|---|---|
| PASS | `results/newman-pass.txt` | 20 | 0 | **0** |
| FAIL | `results/newman-fail.txt` | 20 | 1 | **1** |
| DOWN | `results/newman-down.txt` | 20 | 20 | **1** |

Тестийн нийт тоо: **10 тест, 20 assertion** (`results/newman-pass.txt`-ийн assertions executed тоотой таарна).

Командууд:

```bash
newman run lab05-collection.json 2>&1 | tee results/newman-pass.txt
echo "exit=${PIPESTATUS[0]}"      # exit=0

newman run lab05-collection-fail.json 2>&1 | tee results/newman-fail.txt
echo "exit=${PIPESTATUS[0]}"      # exit=1

# серверийг Ctrl+C-ээр унтрааж
newman run lab05-collection.json 2>&1 | tee results/newman-down.txt
echo "exit=${PIPESTATUS[0]}"      # exit=1
```

**FAIL ба DOWN-ийн ялгаа:** DOWN үед хүсэлт сервер рүү огт хүрээгүй (`ECONNREFUSED`) тул энэ нь интерфейсийн (холболтын) алдаа бөгөөд oracle-ийн алдаа биш. Харин FAIL үед сервер хариу өгсөн боловч хариу нь миний зориуд буруу болгосон oracle-ийн хүлээлттэй таараагүй тул энэ нь oracle-ийн алдаа юм. Хоёулаа exit code 1 боловч шалтгаан нь өөр. CI quality gate нь ямар ч тохиолдолд pipeline-ийг зогсооно.

## 5. Дүгнэлт

Дизайны 5 алхмаас хамгийн их бодол шаардсан нь сонголтуудыг тодорхойлж, тэдгээрийн утгуудын хослолоос бодит тест кейс гаргах алхам байлаа. Учир нь аль хослол утга учиртай, аль нь боломжгүйг шийдэх ёстой байсан. Боломжгүй хослол олдсон: байхгүй оюутанд үзсэн хичээл гэж байхгүй, байхгүй хичээлд урьдач нөхцөл гэж байхгүй, тиймээс эдгээр хослолыг тестэд оруулсангүй. Давхар алдааны тестүүд серверийн шалгах дарааллыг харуулсан: оюутан байхгүй, идэвхгүй, хичээл байхгүй, урьдач гэсэн дарааллаар түрүүлж таарсан нь буцна. Тестүүд серверийн дизайнаас гарсан согог олсонгүй, бүх 20 assertion серверийн хуулийн дагуу дамжсан. Харин тест хийх явцад өөрийн тохиргооны алдаа гарсан: URL-ийн ард нэмэлт зай (`%20`) орсноос сервер `ERROR_NOT_FOUND` буцааж байсан бол collection export хийхэд `baseUrl` хоосон гарч Newman дээр `Invalid URI` алдаа өгч байсан. Эдгээр нь Postman дээр ажиллаж байсан ч командын мөрөөс ажиллуулахад л илэрсэн тул Newman-аар автоматжуулах нь хэрэгтэйг харуулсан. Нэг тест бүр өөрийн setup-тай, өөр ID ашигласнаар тестүүд хоорондоо хамаарахгүй, дарааллаас үл хамаарч ажилласан. FAIL ба DOWN ажиллуулалтууд нь oracle-ийн алдаа ба интерфейсийн алдааг ялгаж харуулсан. Нэг ажиллуулалтаас нөгөөд шилжихэд exit code 0 ба 1 байсан нь CI quality gate-ийн зарчмыг ойлгоход тусалсан.
